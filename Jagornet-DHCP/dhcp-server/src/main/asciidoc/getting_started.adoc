== Getting Started

=== System requirements
Jagornet DHCP Server requires any platform with a certified Java 21+ runtime environment.

The server has been successfully tested on Linux, Windows and Mac OS
using Eclipse Temurin, Oracle JDK, and OpenJDK 21 for the respective platforms.

=== Installation
Java 21+ runtime must be available on the host where the Jagornet DHCP server will be installed. The JAVA_HOME environment variable should be set to the home directory of your Java 21+ JRE or JDK.

. Create the installation directory on the host system and expand the compressed installation file for your target platform.
* Linux/Unix/Mac
** Installation folder: `/opt/jagornet`
** Compressed install file: `jagornet-dhcp-{fullversion}.tar.gz`
** `JAGORNET_DHCP_HOME=/opt/jagornet/jagornet-dhcp-{fullversion}`
* Windows
** Installation folder: `C:\jagornet`
** Compressed install file: `jagornet-dhcp-{fullversion}.zip`
** `JAGORNET_DHCP_HOME=C:\jagornet\jagornet-dhcp-{fullversion}`
. After extracting the compressed files, a jagornet-dhcp-{fullversion} directory will be created in the installation folder, with the following contents.
* `JAGORNET_DHCP_HOME/bin` - executable command line files. See the section on <<Running the Server>>.
* `JAGORNET_DHCP_HOME/config` - configuration files. See the section on Configuration.
* `JAGORNET_DHCP_HOME/db` - database directory. See the section on Binding Database.
* `JAGORNET_DHCP_HOME/docs` - documentation files.
* `JAGORNET_DHCP_HOME/lib` - Java library files.
* `JAGORNET_DHCP_HOME/log` - server output files. See the section on Logging.

=== Running the Server
NOTE: To start the Jagornet DHCP Server, you must have superuser or administrator 
access rights on the host system because the server must bind to privileged port 
numbers 67 for DHCPv4 and 547 for DHCPv6 to service client requests. Optionally, 
the server can be instructed to bind to different port numbers for testing purposes 
only. See the <<Startup Options>> for more information.

IMPORTANT: Ensure that the host system's firewall, if any, is configured to 
enable inbound and outbound traffic for the UDP ports of the DHCPv4 and DHCPv6 server.

IMPORTANT: Ensure that DHCP relay agents on network routers are configured to relay
DHCP traffic from the client subnet(s) to the IP address of the Jagornet DHCP server.
Enable DHCPv4 and DHCPv6 UDP port traffic on all intervening network equipment.

==== Network Deployment Models

In enterprise deployments, Jagornet DHCP Server generally operates in one of two network topologies:

===== 1. Relayed Subnets (Standard Enterprise Model)

In most networks, the DHCP server is centralized in a management VLAN or data center, while clients reside on separate access VLANs across routers or layer-3 switches.

[source]
----
 +-------------+       Broadcast       +--------------------------+
 | DHCP Client | --------------------> | Router / Layer-3 Switch  |
 +-------------+                       | (DHCP Relay Agent)       |
                                       +--------------------------+
                                                    |
                                                    | Unicast UDP 67/547
                                                    | (giaddr set to client subnet)
                                                    v
                                       +--------------------------+
                                       |   Jagornet DHCP Server   |
                                       +--------------------------+
----

* *Router Configuration:* Configure your switch or router interface with an `ip helper-address` (Cisco) or `dhcp-relay` (Juniper/Arista) pointing to the Jagornet server IP.
* *Server Binding:* Start the server with `-4u <server-ip>` or bind to all unicast interfaces (default).
* *Subnet Matching:* The relay agent sets `giaddr` to the client's gateway IP. Jagornet maps `giaddr` directly against the `<address>` defined in your `link` configuration (e.g. `10.100.1.0/24`).

===== 2. Local Broadcast Subnets (Direct Attachment)

When the server is directly attached to the same broadcast domain as the clients:

* *DHCPv4:* The server must listen for broadcast packets by specifying the interface at startup:
+
[source,bash]
----
sudo ./bin/dhcpserver -4b eth0 -c config/dhcpserver.yaml
----
* *Subnet Matching:* Because `giaddr` is `0.0.0.0`, Jagornet matches the request against the link whose network CIDR matches the primary IP address configured on `eth0`.

==== Linux/Mac
The $JAGORNET_DHCP_HOME/bin/dhcpserver script can be used to operate the server
from a command shell. This script supports the following options:

`start [startup options]` - starts the server with any startup options provided.

`stop` - stops the server.

`restart [startup options]` - stop and start the server.

`status` - check if the server is running.

`version` - display server version and exit.  A convenience option which can be used instead of 'start -v' or 'start --version'.

`test-configfile <configfile>` - test server configuration file and exit. A convenience option instead of 'start -tc <filename>' or 'start --test-configfile <filename>'.

`list-interfaces` - list host interfaces and exit. A convenience method instead of 'start -li' or 'start --list-interfaces'.

Startup examples:

. Display the server version and exit:

 $JAGORNET_DHCP_HOME/bin/dhcpserver -v

. Display the startup options and exit (instant response):

 $JAGORNET_DHCP_HOME/bin/dhcpserver --help

. Start the server with default options:

 $JAGORNET_DHCP_HOME/bin/dhcpserver

. Start the server on a test DHCPv4 port with broadcast on 'eth0':
 
 $JAGORNET_DHCP_HOME/bin/dhcpserver -4p 10067 -4b eth0

. Start the server on a test DHCPv6 port with multicast on all IPv6 multicast interfaces:
 
 $JAGORNET_DHCP_HOME/bin/dhcpserver -6p 10547 -6m

. Start the server with support for DHCPv4 broadcast on 'eth0' and DHCPv6 multicast on 'eth1':

 $JAGORNET_DHCP_HOME/bin/dhcpserver -4b eth0 -6m eth1

. Start the server with an alternate configuration file, one unicast address, and two multicast interfaces:

 $JAGORNET_DHCP_HOME/bin/dhcpserver -c config/my-dhcpserver.xml -6u 2001:db8::1 -6m eth0 eth1

===== Linux Systemd Service

Jagornet DHCP Server includes automated service installation and uninstallation scripts in `$JAGORNET_DHCP_HOME/bin/`.

The installer script handles creating the `/opt/jagornet/dhcp` symlink, creating the unprivileged `jagornet` system user and group, setting proper file permissions, creating an environment file at `/etc/default/jagornet-dhcp`, and registering and starting the systemd service.

. Install and start the systemd service:

 sudo $JAGORNET_DHCP_HOME/bin/install-service.sh

NOTE: You can pass `--no-start` to install and enable the service on boot without starting it immediately: `sudo ./bin/install-service.sh --no-start`. Run `sudo ./bin/install-service.sh --help` for all options.

. Manage the service:

 sudo systemctl status jagornet-dhcp
 sudo systemctl stop jagornet-dhcp
 sudo systemctl restart jagornet-dhcp
 sudo journalctl -u jagornet-dhcp -f

. Uninstall the service:

 sudo $JAGORNET_DHCP_HOME/bin/uninstall-service.sh

NOTE: Pass `--remove-symlink` to also clean up the `/opt/jagornet/dhcp` symlink: `sudo ./bin/uninstall-service.sh --remove-symlink`. Application configuration, databases, and logs are preserved.

==== Windows
===== Command Shell

The `%JAGORNET_DHCP_HOME%\bin\dhcpserver.bat` batch file is used to operate the server from a command prompt. Provide any desired startup options on the command line. Press `Ctrl+C` in the command prompt to stop the server.

Startup examples:

. Display the startup options and exit:

 %JAGORNET_DHCP_HOME%\bin\dhcpserver.bat --help

. Start the server with default options:

 %JAGORNET_DHCP_HOME%\bin\dhcpserver.bat

. Start the server with a specific configuration file:

 %JAGORNET_DHCP_HOME%\bin\dhcpserver.bat -c config\my-dhcpserver.xml

. Start the server on a test DHCPv4 port with support for broadcast on the IPv4 broadcast-enabled interface named 'eth0':
 
 %JAGORNET_DHCP_HOME%\bin\dhcpserver.bat -4p 10067 -4b eth0

. Start the server on a test DHCPv6 port with support for multicast on all IPv6 multicast-enabled interfaces:
 
 %JAGORNET_DHCP_HOME%\bin\dhcpserver.bat -6p 10547 -6m

. Start the server with support for DHCPv4 broadcast on the interface named 'eth0' and DHCPv6 multicast on the interface named 'eth1':

 %JAGORNET_DHCP_HOME%\bin\dhcpserver.bat -4b eth0 -6m eth1

. Start the server with an alternate configuration file, one specific unicast address, and two specific multicast interfaces:

 %JAGORNET_DHCP_HOME%\bin\dhcpserver.bat -c config\my-dhcpserver.xml -6u 2001:db8::1 -6m eth0 eth1

===== Windows Service (WinSW)

Jagornet DHCP Server can operate as a Microsoft Windows Service using https://github.com/winsw/winsw[WinSW (Windows Service Wrapper)]. The wrapper is pre-bundled as `%JAGORNET_DHCP_HOME%\bin\jagornet-service.exe` with its configuration `%JAGORNET_DHCP_HOME%\bin\jagornet-service.xml`.

1. Run `%JAGORNET_DHCP_HOME%\bin\winsw-install.bat` as Administrator to install and start the service.
2. Manage the service using Windows Services (`services.msc`) or `%JAGORNET_DHCP_HOME%\bin\jagornet-service.exe [start|stop|status]`.
3. Run `%JAGORNET_DHCP_HOME%\bin\winsw-uninstall.bat` as Administrator to remove the service.

==== Docker / Container Deployment

Jagornet DHCP Server is available as an optimized, multi-architecture OCI/Docker container image.

To run the container attached to the host network (required for standard broadcast and multicast DHCP traffic):

[source,bash]
----
docker run -d \
  --name jagornet-dhcp \
  --net=host \
  -v /path/to/my/config:/app/config \
  jagornet/dhcp-server:{fullversion}
----

The container runs with `/app` as its working directory and mounts configuration files under `/app/config`. By default, the container starts with `/app/config/dhcpserver-jib.json`, which binds the server without serving any client links until custom configuration is mounted.

=== Testing and Simulation Tools

Jagornet DHCP Server includes built-in command-line utilities in `$JAGORNET_DHCP_HOME/bin/` to simplify local testing, configuration generation, and traffic simulation without requiring client hardware or administrator privileges.

==== Test Configuration Generator (`gentestconfig`)

The `gentestconfig` utility automatically inspects active host network interfaces, discovers the local IP subnet, and generates a working configuration file tailored to the local environment.

[source,bash]
----
# Generate a test configuration for a specific network interface:
./bin/gentestconfig -v 4 -i eth0 -f config/dhcpserver-test.xml

# Show all options:
./bin/gentestconfig --help
----

*Options:*

* `-i, --interface <name>`: Network interface to inspect (e.g. `eth0`, `en0`). Defaults to the first active interface.
* `-v, --version <4|6|both>`: Protocol version to generate (default: `both`).
* `-f, --filename <file>`: Output configuration file path (default: `dhcpserver-test-config.xml`).

==== DHCPv4 Client Simulator (`testclientv4`)

The `testclientv4` utility simulates DHCPv4 client requests (DISCOVER -> OFFER -> REQUEST -> ACK -> RELEASE) directly to a target server. It behaves like a DHCP relay agent communicating unicast with the server, making it possible to test lease allocation on arbitrary test ports.

[source,bash]
----
# Run 25 client requests against an unprivileged test port:
./bin/testclientv4 -sp 10067 -n 25

# Simulate requests with FQDN / hostname options:
./bin/testclientv4 -sp 10067 -hn

# Show all options:
./bin/testclientv4 --help
----

*Key Options:*

* `-sp, --serverport <port>`: Destination server port (default: 67).
* `-cp, --clientport <port>`: Source port for receiving server replies. When `-sp` is set to an unprivileged port, `-cp` automatically defaults to `serverport + 1` to prevent port collisions on the same host.
* `-n, --number <count>`: Number of simulated client requests to send (default: 100).
* `-hn, --hostname`: Include DHCPv4 Host Name option in requests.
* `-x, --release`: Send DHCPRELEASE messages after acquiring leases.
* `-rr, --requestrate <rate>`: Throttle transmission to a maximum request rate per second.

==== DHCPv6 Client Simulator (`testclientv6`)

The `testclientv6` utility simulates DHCPv6 client requests (SOLICIT -> ADVERTISE -> REQUEST -> REPLY) for stateful IPv6 address assignments.

[source,bash]
----
# Run client requests against a DHCPv6 test port:
./bin/testclientv6 -p 10547 -n 10

# Show all options:
./bin/testclientv6 --help
----

=== Logging
Logging for the Jagornet DHCP server is performed using the 
https://logging.apache.org/log4j/2.x/[Apache Log4j 2] logging 
logging service. The Log4j2 configuration file is located in the `config/log4j2.xml` 
file. The server writes all initial startup messages to the standard output and 
error streams. After the server initialization, all messages will be written to
the `log/dhcpserver.log` file. When the file reaches 10MB, it is "rolled" over to a 
new `log/dhcpserver-#.log` file up to ten files of logging history. These settings are 
controlled by the  
https://logging.apache.org/log4j/2.x/manual/appenders.html#RollingFileAppender[Log4j2 RollingFileAppender].
